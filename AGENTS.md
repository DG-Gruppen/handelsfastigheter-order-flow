# Project rules

- News MP4 attachments use private storage with resumable uploads; readers receive short-lived signed URLs only for accessible articles, and editors confirm persisted rows before reporting success and invalidate both news queries.

- Knowledge-base mutations must confirm a returned row before displaying success and invalidate the shared knowledge-base query after persistence, so failed writes and stale lists cannot look like successful publication.
- Content-index trigger upserts must use (source_table, source_id, chunk_index), with chunk_index 0 for unchunked sources, because the index is unique per source chunk rather than per source.
- Knowledge-base deletes archive complete rows transactionally through database triggers; restoration is editor-only, checks expiry server-side and restores articles/videos as drafts to avoid accidental republication and notifications. Used categories cannot be deleted to preserve associations; expired archive rows are purged daily.
- Document previews classify by MIME and filename, render PDF, modern Word, spreadsheets, sanitized HTML and media locally, and require explicit consent before sharing legacy Word or PowerPoint signed URLs with Microsoft's viewer; spreadsheet previews never execute macros.- `database-backup` edge function streams table rows to JSON strings per table (never a full object graph) and, for Google Drive upload, gzips the JSON via `CompressionStream` while writing chunk-by-chunk — the full 55 MB string is never assembled on the Drive path, because the worker OOMs (WORKER_RESOURCE_LIMIT) otherwise. Drive uploads go through the connector gateway (`GOOGLE_DRIVE_API_KEY` + `LOVABLE_API_KEY`) into folder "SHF Intra Backups" as `.json.gz`.
